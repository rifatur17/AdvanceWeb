## Prerequisites and database setup

Use Node.js 22 or later, npm, and PostgreSQL 13 or later. Install PostgreSQL and use a local account you control. Create separate application and test databases in psql or pgAdmin:

```sql
CREATE DATABASE advanceweb_lab1;
CREATE DATABASE advanceweb_lab1_test;
```

From PowerShell:

```powershell
cd 'C:\Test\AdvanceWeb\Mid\Lab task 1\product-management'
npm.cmd ci
Copy-Item .env.example .env
# Edit .env: set your database host, port, user and password.
npm.cmd run migration:run
npm.cmd run start:dev
```

If `.env` already exists, edit it instead of copying over it. The implementation machine has an ignored local `.env` using PostgreSQL on port **55432**. The sample uses the normal PostgreSQL port **5432**. Neither database passwords nor the real `.env` belong in Git.

Configuration: `PORT` (default 3000), `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_DATABASE`, and `TEST_DB_DATABASE`. The app binds to `127.0.0.1`. The migration creates `products` and `employees` tables with database-generated UUID v4 IDs, non-null fields, and nonnegative numeric constraints. Schema synchronization is disabled; migrations must be run explicitly. `migration:rollback` reverts the last migration and **drops both tables**, so use it only on a disposable database.

## Endpoints

Base URL: `http://127.0.0.1:3000`. There is no `/api` prefix.

| Method | Products | Employees | Success |
| --- | --- | --- | --- |
| POST | /products | /employees | 201, saved entity including UUID |
| GET | /products | /employees | 200, array of saved entities |
| GET | /products/:id | /employees/:id | 200, matching entity |
| PATCH | /products/:id | /employees/:id | 200, updated entity |
| DELETE | /products/:id | /employees/:id | 200, `{ "message": "... deleted successfully", "id": "..." }` |

Product POST example:

```json
{"name":"Notebook","category":"Stationery","price":125.5,"quantity":20}
```

Employee POST example:

```json
{"name":"Lab Employee","email":"lab@example.com","phone":"+8801700000000","password":"dummy-only","age":25,"yearsOfWorking":3}
```

PATCH accepts one or more supplied fields, e.g. `{"price":135.75,"quantity":12}` or `{"yearsOfWorking":4}`. Unchanged fields retain their values. IDs are generated by PostgreSQL and cannot be supplied or changed in request bodies.

Validation rejects unknown fields, missing required POST fields, nulls, blank strings, malformed emails, numeric strings, negative numbers, fractional integer fields, oversized integers, nonfinite prices, and empty PATCH bodies. Text fields allow at most 255 characters. Invalid UUIDs return 400, and valid UUIDs without matching records return 404. Database constraint errors return safe 400 responses, conflicts return 409, and other TypeORM errors return 500 without SQL or connection details. Employee passwords are dummy strings returned as required fields; this is a course CRUD model, so use only dummy values.
